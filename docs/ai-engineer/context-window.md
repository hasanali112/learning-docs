# Context Window

**Context window হলো একটা model একবারে সর্বোচ্চ কত token দেখতে পারে। Input আর output, দুটো মিলিয়ে এই সীমার ভেতরে থাকতে হয়।**

[LLM এর মূল ধারণা](/ai-engineer/llm-basics) নোটে এর ছোট পরিচয় ছিল। এখানে দেখবো বাস্তবে এটা কীভাবে ভরে যায়, আর কীভাবে সামলাতে হয়।

## কাজের টেবিলের মতো ভাবো

Context window একটা টেবিলের মতো। Model শুধু টেবিলে যা আছে সেটাই দেখতে পায়, ঘরের বাকি কিছু না। টেবিল ছোট, তাই কী রাখবে সেটা বেছে নিতে হয়।

```txt
┌─────────────── context window ───────────────┐
│ System prompt        (সবসময়)                  │
│ উদাহরণ               (সবসময়)                  │
│ পুরনো কথোপকথন         (বাড়তে থাকে)            │
│ RAG থেকে আনা তথ্য     (প্রশ্ন অনুযায়ী)           │
│ Tool এর ফলাফল        (agent ডাকলে)            │
│ নতুন মেসেজ                                    │
│ ── উত্তরের জন্য জায়গা ──                        │
└───────────────────────────────────────────────┘
```

## বড় context মানেই ভালো না

আজকের অনেক model এর context window অনেক বড়। কিন্তু সব ঢুকিয়ে দেওয়া ভালো উপায় না:

| সমস্যা | কেন |
|---|---|
| **খরচ** | প্রতিটা call এ সব token এর দাম দিতে হয় |
| **ধীর** | input যত লম্বা, প্রথম token আসতে তত দেরি ([Inference](/ai-engineer/inference)) |
| **মনোযোগ হারানো** | অনেক model এর ক্ষেত্রে দেখা গেছে, লম্বা context এর মাঝখানের তথ্য শুরু বা শেষের তথ্যের চেয়ে বেশি মিস হয় |
| **ভুল পথে যাওয়া** | অদরকারি বা পুরনো তথ্য model কে বিভ্রান্ত করতে পারে |

::: tip নিয়ম
যতটুকু দরকার, ঠিক ততটুকু দাও। কম কিন্তু সঠিক তথ্য, বেশি কিন্তু এলোমেলো তথ্যের চেয়ে ভালো ফল দেয়।
:::

## সামলানোর ৫টা উপায়

| উপায় | কী করে | কখন |
|---|---|---|
| **ছাঁটা** (trimming) | শুধু শেষ কয়েকটা মেসেজ রাখা | ছোট, সাধারণ কথোপকথন |
| **সংক্ষেপ** (summarization) | পুরনো কথার একটা ছোট সারাংশ রাখা | লম্বা কথোপকথন, পুরনো কথাও জরুরি |
| **গোছানো অবস্থা রাখা** | কথার বদলে পূরণ হওয়া ফর্মটাই রাখা | আমাদের order ফর্ম: "কী জানা গেছে" সেটাই আসল |
| **RAG** | সব তথ্য না দিয়ে শুধু দরকারিটা খুঁজে দেওয়া | বড় document |
| **ছোট tool ফলাফল** | tool শুধু দরকারি ঘরগুলো ফেরত দেবে | database query |

LangChain এ শেষ কয়েকটা মেসেজ রাখার তৈরি function আছে:

```python
from langchain_core.messages import trim_messages

trimmed = trim_messages(
    history,
    max_tokens=2000,
    strategy="last",          # শেষেরগুলো রাখো
    token_counter=model,      # model দিয়েই token গোনা
    include_system=True,      # system prompt কখনো বাদ দিও না
    start_on="human",         # কাটার পর তালিকা কাস্টমারের মেসেজ দিয়ে শুরু
)
```

## আমাদের Sales agent এ

একজন কাস্টমার কয়েক দিন ধরে কথা বলতে পারে। সব কথা রাখলে context ভরে যাবে। ভালো উপায় হলো **পূরণ হওয়া `OrderForm` টাই অবস্থা হিসেবে রাখা**, আর শুধু শেষ কয়েকটা মেসেজ পুরোটা দেওয়া। একশো মেসেজের বদলে একটা ছোট ফর্ম, যেখানে লেখা আছে কী জানা গেছে আর কী বাকি।

এই ধারণাটার বড় রূপ হলো [Context Engineering](/ai-engineer/context-engineering)।

## যা নিয়ে গোলমাল হয়

- **Context window আর memory এক না।** Context হলো একটা call এ model যা দেখে। Memory হলো আমাদের app যা জমা রাখে আর প্রতিটা call এ বেছে বেছে context এ দেয়।
- **Output ও context এর ভেতরে।** Input দিয়ে পুরো সীমা ভরে ফেললে উত্তরের জায়গা থাকে না।
- **Bangla তে context তাড়াতাড়ি ভরে।** একই কথায় সাধারণত বেশি token লাগে।
