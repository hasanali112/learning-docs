# Sampling Parameters

**Model প্রতিটা ধাপে পরের token এর একটা সম্ভাবনার তালিকা বানায়। সেই তালিকা থেকে কোন token বাছা হবে, সেটা ঠিক করে sampling parameter গুলো।**

[LLM এর মূল ধারণা](/ai-engineer/llm-basics) নোটে দেখেছি LLM একটা একটা করে token অনুমান করে লেখে। এখানে দেখবো সেই "বাছাই" ধাপটা কীভাবে নিয়ন্ত্রণ করা যায়।

## Core LLM Elements এর মধ্যে এটা কোথায়

| অংশ | কী | নোট |
|---|---|---|
| Token | লেখার ছোট টুকরো, model যা দেখে আর লেখে | [LLM এর মূল ধারণা → Token](/ai-engineer/llm-basics#token) |
| Context | model একবারে যা দেখতে পারে | [Context Window](/ai-engineer/context-window) |
| Sampling Parameters | পরের token কীভাবে বাছা হবে | এই পাতা |

## আগে বোঝো: sampling মানে লটারি

Model সরাসরি একটা উত্তর দেয় না, দেয় সম্ভাবনা:

```txt
"আজ আকাশ ___"

  নীল      ██████████  ৫০%
  মেঘলা    █████       ২৫%
  পরিষ্কার  ███         ১৫%
  সুন্দর    █            ৭%
  বেগুনি    ▌            ৩%
```

এখান থেকে বাছার দুটো উপায়:
- **সবসময় সবচেয়ে বড়টা নাও** (greedy): প্রতিবার "নীল"। উত্তর স্থির, কিন্তু একঘেয়ে আর মাঝে মাঝে একই কথা ঘুরে ফিরে আসে।
- **লটারি করো** (sampling): বেশিরভাগ সময় "নীল", মাঝে মাঝে "মেঘলা"। উত্তর বেশি স্বাভাবিক, কিন্তু খুব কম সম্ভাবনায় "বেগুনি"-ও চলে আসতে পারে।

Sampling parameter গুলো এই লটারির নিয়ম ঠিক করে: লটারি কতটা এলোমেলো হবে, কোন টিকিটগুলো লটারিতে থাকবে, আর আগে আসা token কতটা শাস্তি পাবে।

## Temperature

**Temperature ঠিক করে লটারি কতটা এলোমেলো হবে।** এটা সম্ভাবনার তালিকাকে সরু (নিশ্চিত) বা চওড়া (এলোমেলো) করে।

একই উদাহরণে:

| Token | আসল | T = ০.৫ (কম) | T = ২ (বেশি) |
|---|---|---|---|
| নীল | ৫০% | ≈৭৩% | ≈৩৫% |
| মেঘলা | ২৫% | ≈১৮% | ≈২৫% |
| পরিষ্কার | ১৫% | ≈৭% | ≈১৯% |
| সুন্দর | ৭% | ≈১% | ≈১৩% |
| বেগুনি | ৩% | প্রায় ০% | ≈৮% |

- **কম temperature:** যে আগে থেকেই এগিয়ে, সে আরও এগিয়ে যায়। উত্তর স্থির আর নিরাপদ। ০ হলে প্রায় সবসময় সবচেয়ে সম্ভাব্যটা।
- **বেশি temperature:** সবাই কাছাকাছি চলে আসে। উত্তর বৈচিত্র্যময়, কিন্তু উল্টাপাল্টা কথার ঝুঁকিও বাড়ে।

::: tip মনে রাখার কৌশল
ঠান্ডা পানির অণু শান্ত, এক জায়গায় থাকে → কম temperature = স্থির উত্তর।
গরম পানির অণু ছোটাছুটি করে → বেশি temperature = এলোমেলো উত্তর।
:::

## Top-K

**Top-K বলে: শুধু সবচেয়ে সম্ভাব্য K টা token লটারিতে রাখো, বাকিদের বাদ দাও।**

Top-K = ৩ হলে:

```txt
  নীল      ৫০%  ✅
  মেঘলা    ২৫%  ✅
  পরিষ্কার  ১৫%  ✅
  সুন্দর     ৭%  ❌ বাদ
  বেগুনি     ৩%  ❌ বাদ

বাকি ৩টার মধ্যে নতুন করে ভাগ:
  নীল ≈৫৬%, মেঘলা ≈২৮%, পরিষ্কার ≈১৭%
```

এখন "বেগুনি" আর কোনোভাবেই আসবে না।

**সমস্যা:** K সবসময় একই সংখ্যা, model কতটা নিশ্চিত সেটা দেখে না।

```txt
"বাংলাদেশের রাজধানী ___"

  ঢাকা       ৯৫%  ✅
  চট্টগ্রাম    ৩%  ✅  ← ভুল উত্তর, তবু লটারিতে থাকলো
  খুলনা       ১%  ✅  ← এটাও
```

Model প্রায় নিশ্চিত যে উত্তর "ঢাকা", কিন্তু Top-K = ৩ জোর করে আরও দুটো ভুল উত্তর লটারিতে রেখে দিল। এই সমস্যার সমাধান Top-P।

## Top-P

**Top-P (nucleus sampling) বলে: ওপর থেকে token নিতে থাকো, যতক্ষণ না তাদের মোট সম্ভাবনা P এ পৌঁছায়। বাকিদের বাদ দাও।**

Top-P = ০.৭ (৭০%) হলে:

```txt
"আজ আকাশ ___"                     মোট
  নীল      ৫০%  ✅                ৫০%
  মেঘলা    ২৫%  ✅                ৭৫%  ← ৭০% পার হলো, থামো
  পরিষ্কার  ১৫%  ❌ বাদ
  ...
```

একই Top-P = ০.৭, অন্য প্রশ্নে:

```txt
"বাংলাদেশের রাজধানী ___"          মোট
  ঢাকা       ৯৫%  ✅               ৯৫%  ← প্রথমটাতেই ৭০% পার, থামো
  চট্টগ্রাম    ৩%  ❌ বাদ
```

**Top-P এর সুবিধা:** model নিশ্চিত হলে লটারিতে কম token থাকে, অনিশ্চিত হলে বেশি। নিজে থেকেই মানিয়ে নেয়।

| | Top-K | Top-P |
|---|---|---|
| কী গোনে | token এর **সংখ্যা** | সম্ভাবনার **যোগফল** |
| Model নিশ্চিত হলে | তবু K টা রাখে | ১-২টা রাখে |
| Model অনিশ্চিত হলে | তবু K টা রাখে | অনেকগুলো রাখে |

## Repetition Penalties

LLM মাঝে মাঝে একই কথা ঘুরে ফিরে বলে, এমনকি লুপে আটকে যায়:

```txt
"আমাদের শাড়ি খুব ভালো। আমাদের শাড়ি খুব ভালো। আমাদের শাড়ি খুব..."
```

**Repetition penalty হলো আগে আসা token এর সম্ভাবনা কমিয়ে দেওয়া**, যাতে model নতুন শব্দ ব্যবহার করে।

API ভেদে দুই রকম penalty দেখা যায়:

| নাম | কীভাবে শাস্তি দেয় | উদাহরণ |
|---|---|---|
| **Frequency penalty** | token যতবার এসেছে, শাস্তি তত বেশি | "ভালো" ৫ বার এলে, ১ বার আসার চেয়ে অনেক বেশি শাস্তি |
| **Presence penalty** | একবার এলেই একই শাস্তি, কতবার সেটা দেখে না | নতুন বিষয়ে কথা বলতে উৎসাহ দেয় |

::: warning বেশি দিলে উল্টো সমস্যা
Penalty খুব বেশি হলে model দরকারি শব্দও এড়াতে শুরু করে। যেমন "শাড়ি" শব্দটা আবার লিখতে না পেরে অদ্ভুত প্রতিশব্দ খোঁজে। সাধারণত ছোট মান দিয়ে শুরু করো, বা একদম না দিয়ে।
:::

## কোন কাজে কী দেবো

| কাজ | Temperature | Top-P | Penalty |
|---|---|---|---|
| মেসেজ থেকে order এর ফর্ম পূরণ, তথ্য বের করা | কম (০ এর কাছে) | default | না |
| কাস্টমারকে উত্তর দেওয়া (sales agent) | মাঝারি | default | না বা খুব কম |
| Facebook post, নতুন আইডিয়া | বেশি | default বা একটু বেশি | একটু |

## কাজের নিয়ম

1. **সাধারণত একটা জিনিসই বদলাও।** Temperature আর Top-P দুটোই লটারির এলোমেলোভাব নিয়ন্ত্রণ করে, তাই দুটো একসাথে বদলালে কোনটার কী প্রভাব বোঝা কঠিন। বেশিরভাগ ক্ষেত্রে শুধু temperature বদলালেই চলে।
2. **সব API সব parameter দেয় না।** কোনো API তে top_k আছে, কোনোটায় নেই। কোনোটায় frequency/presence penalty আছে, কোনোটায় নেই। কিছু নতুন model এ এগুলো বদলানোই যায় না। ব্যবহারের আগে সেই API এর docs দেখো।
3. **Temperature ০ মানে ১০০% একই উত্তর না।** প্রায় একই আসবে, তবে হুবহু একই হওয়ার নিশ্চয়তা নেই।
4. **Sampling দিয়ে ভুল তথ্য ঠিক হয় না।** Temperature কমালে উত্তর স্থির হয়, সঠিক হয় না। Model ভুল জানলে স্থিরভাবেই ভুল বলবে। সঠিক তথ্যের জন্য database বা [RAG](/ai-engineer/rag)।

## এক নজরে

```txt
Temperature   → লটারি কতটা এলোমেলো       (তালিকা সরু / চওড়া)
Top-K         → ওপরের K টা রাখো           (সংখ্যা দিয়ে কাটা)
Top-P         → মোট P% পর্যন্ত রাখো         (সম্ভাবনা দিয়ে কাটা)
Repetition    → আগে আসা token এ শাস্তি      (একই কথা কম)
```
