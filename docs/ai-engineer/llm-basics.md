# LLM এর মূল ধারণা

LangChain বা agent শুরু করার আগে বুঝতে হবে ভেতরের ইঞ্জিনটা আসলে কী করে। এই পেজের প্রতিটা ধারণা পরে প্রতিদিনের কাজে লাগবে: খরচ কেন বাড়ছে, agent কেন ভুল বলছে, memory কেন আমাদেরই সামলাতে হয়।

## LLM আসলে কী করে

**LLM (Large Language Model) এর কাজ একটাই: লেখার পরের টুকরোটা কী হবে, সেটা অনুমান করা।**

ফোনের keyboard এ "আমি ভাত" লিখলে পরের শব্দ হিসেবে "খাই" আসে। LLM একই কাজ করে, শুধু অনেক বড় পরিসরে। এটা internet এর বিশাল পরিমাণ লেখা পড়ে শিখেছে কোন লেখার পরে সাধারণত কী আসে।

নিচের animation টা দেখো। নিজে থেকে চলবে, চাইলে থামিয়ে আগে-পিছে যেতে পারো।

<FlowSteps v-bind="writeFlow" />

::: warning এর মানে: LLM database না
LLM এর ভেতরে "সত্য" জমা থাকে না, থাকে "কোন লেখা কেমন শোনায়" এর ধারণা। তাই সে খুব আত্মবিশ্বাসের সাথে ভুল বলতে পারে, যেমন উপরের উদাহরণে বানানো দাম "১৮৫০ টাকা"। একে বলে **hallucination**।

সমাধান: দাম বা স্টকের মতো তথ্য LLM এর স্মৃতি থেকে না নিয়ে **database থেকে tool দিয়ে এনে** তাকে দেওয়া। এটা আমরা পর্ব ২ তে করব।
:::

## Token

Model অক্ষর বা শব্দ দেখে না, দেখে **token**: লেখার ছোট টুকরো। একটা token কখনো পুরো শব্দ, কখনো শব্দের অংশ, কখনো শুধু একটা চিহ্ন।

কেন জানা দরকার:
- **খরচ token এ হিসাব হয়।** API তে তুমি যত token পাঠাও আর যত token ফেরত পাও, তার জন্য টাকা দাও।
- **Bangla তে সাধারণত বেশি token লাগে।** বেশিরভাগ tokenizer ইংরেজি লেখা বেশি দেখে বানানো, তাই একই কথা Bangla তে লিখলে প্রায়ই বেশি টুকরো হয়। মানে খরচ বেশি, আর context তাড়াতাড়ি ভরে।
- **উত্তর token এ token এ আসে।** তাই লম্বা উত্তর মানে বেশি সময়।

| | Input token (পাঠানো) | Output token (ফেরত) |
|---|---|---|
| কী | system prompt, পুরনো কথা, কাস্টমারের মেসেজ | model এর লেখা উত্তর |
| দাম | কম | সাধারণত বেশি |
| গতি | একসাথে পড়া হয়, দ্রুত | একটা একটা করে লেখা হয়, ধীর |

## Context window

**Context window হলো model একবারে সর্বোচ্চ কত token দেখতে পারে।** এর ভেতরে সবকিছু ধরতে হয়:

```txt
┌────────────── context window ──────────────┐
│ system prompt (নিয়ম)                         │
│ উদাহরণ (few-shot)                           │
│ পুরনো কথোপকথন                               │
│ tool এর ফলাফল (যেমন database থেকে আনা order)   │
│ কাস্টমারের নতুন মেসেজ                         │
│ model এর উত্তর                               │
└─────────────────────────────────────────────┘
```

সীমা পার হলে API error দেয়, বা পুরনো কথা বাদ দিতে হয়। Model ভেদে এই সীমা আলাদা। আর সীমার ভেতরে থাকলেও, যত বেশি জিনিস ঢোকাবে, খরচ তত বাড়বে আর জরুরি তথ্য তত হারিয়ে যাওয়ার ঝুঁকি। বিস্তারিত: [Context Window](/ai-engineer/context-window)।

## Message এর তিন ধরন

Chat model এ সাধারণ লেখা না পাঠিয়ে **message এর তালিকা** পাঠানো হয়। প্রতিটা message এর একটা ভূমিকা (role) থাকে:

| Role | কে লেখে | কাজ |
|---|---|---|
| `system` | তুমি (developer) | agent এর ভূমিকা, নিয়ম, উত্তরের ধরন। কাস্টমার এটা দেখে না |
| `user` | কাস্টমার | প্রশ্ন বা মেসেজ |
| `assistant` | model | model এর আগের উত্তর |

```python
messages = [
    {"role": "system", "content": "তুমি একটা অনলাইন দোকানের সহকারী। শুধু দোকানের বিষয়ে উত্তর দাও।"},
    {"role": "user", "content": "লাল শাড়ি আছে?"},
]
```

পরে tool ব্যবহার করলে চতুর্থ একটা ধরন আসবে: `tool`, যেখানে tool এর ফলাফল থাকে।

## Temperature

Model পরের token বাছার সময় কতটা "ঝুঁকি" নেবে, সেটা ঠিক করে temperature।

| Temperature | আচরণ | কোথায় |
|---|---|---|
| কম (০ এর কাছে) | প্রায় সবসময় সবচেয়ে সম্ভাব্য token, উত্তর বেশি স্থির | **ফর্ম পূরণ, তথ্য বের করা, হিসাব** |
| বেশি | মাঝে মাঝে অপ্রত্যাশিত token, উত্তর বেশি বৈচিত্র্যময় | Facebook post এর লেখা, নতুন আইডিয়া |

আমাদের প্রথম কাজ (মেসেজ থেকে order এর ফর্ম পূরণ) এ temperature কম রাখব, কারণ একই মেসেজে প্রতিবার একই ফর্ম চাই। তবে মনে রাখো, temperature ০ হলেও প্রতিবার হুবহু একই উত্তরের নিশ্চয়তা নেই।

## LLM কিছু মনে রাখে না

**প্রতিটা API call সম্পূর্ণ নতুন।** আগের call এ কী কথা হয়েছে, model তা জানে না। ChatGPT তে কথোপকথন মনে থাকে বলে মনে হয়, কারণ ChatGPT এর app প্রতিবার আগের সব কথা আবার পাঠায়।

<FlowSteps v-bind="memoryFlow" />

এর তিনটা ফল:
1. **Memory সামলানো আমাদের কাজ।** প্রতিটা কাস্টমারের কথোপকথন আলাদা করে জমা রাখতে হবে। কাজের তালিকার ধাপ ৫ এ এটা করব।
2. **কথোপকথন যত লম্বা, প্রতিটা call তত দামি।** কারণ প্রতিবার পুরো ইতিহাস যায়।
3. **পুরনো কথা ছাঁটতে হয়।** একসময় context window ভরে যাবে, তখন পুরনো অংশ বাদ দিতে বা সংক্ষেপ করতে হয়।

## আমাদের প্রজেক্টে এর মানে

| ধারণা | Sales agent এ কী করব |
|---|---|
| পরের token অনুমান | LLM কে তথ্যের উৎস না, ভাষা বোঝার যন্ত্র হিসেবে ব্যবহার |
| Hallucination | দাম, স্টক, order সবসময় database থেকে |
| Token আর খরচ | system prompt ছোট আর পরিষ্কার রাখা |
| Temperature | ফর্ম পূরণে কম |
| Stateless | প্রতিটা কাস্টমারের কথোপকথন নিজেরা জমা রাখা |
