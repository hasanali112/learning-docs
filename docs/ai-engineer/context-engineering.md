# Context Engineering

**Context engineering হলো প্রতিটা LLM call এ context window এ ঠিক কী কী যাবে, সেটা বেছে আর সাজিয়ে দেওয়া, যাতে model এর সামনে কাজের জন্য যা দরকার ঠিক তাই থাকে, এর বেশি বা কম না।**

## Prompt engineering থেকে context engineering

| | Prompt Engineering | Context Engineering |
|---|---|---|
| কী নিয়ে | নির্দেশ কীভাবে লিখবো | পুরো context এ কী কী যাবে |
| কখন ঠিক হয় | আগে থেকে, একবার লেখা | প্রতিটা call এ, চলার সময় |
| অংশ | system prompt, উদাহরণ | নিয়ম + অবস্থা + history + RAG + tool ফলাফল + tool তালিকা |
| প্রশ্ন | "কীভাবে বলবো?" | "এই মুহূর্তে model এর কী জানা দরকার?" |

[Prompt Engineering](/ai-engineer/prompting) হলো context engineering এর একটা অংশ। একটা সাধারণ chatbot এ prompt ই প্রায় সব। কিন্তু agent এ প্রতিটা ধাপে context বদলায়: নতুন tool ফলাফল আসে, কথা বাড়ে, অবস্থা বদলায়। তখন আসল কাজ হয়ে দাঁড়ায় সঠিক জিনিসটা সঠিক সময়ে দেওয়া।

## Context এ কী কী যেতে পারে

```txt
┌─ নিয়ম আর উদাহরণ ─────────── প্রায় স্থির
├─ Tool এর তালিকা ──────────── agent কী কী করতে পারে
├─ অবস্থা (state) ─────────── যেমন পূরণ হওয়া OrderForm
├─ কথোপকথন ───────────────── শেষ কয়েকটা, বা সারাংশ
├─ খুঁজে আনা তথ্য ─────────── RAG, database
├─ Tool এর ফলাফল ──────────── agent চলার সময় আসে
└─ Output এর আকার ─────────── structured output schema
```

## ৪টা মূল কৌশল

| কৌশল | মানে | আমাদের Sales agent এ |
|---|---|---|
| **লিখে রাখো** (write) | জরুরি তথ্য context এর বাইরে জমা রাখো, দরকার হলে আনো | পূরণ হওয়া ফর্ম database এ, প্রতিবার পুরো কথা না |
| **বেছে আনো** (select) | শুধু এই মুহূর্তের দরকারি জিনিস | কাস্টমার যে product নিয়ে কথা বলছে শুধু তার তথ্য |
| **ছোট করো** (compress) | সারাংশ, ছাঁটা, tool ফলাফল থেকে শুধু দরকারি ঘর | ২০টা order এর পুরো বিবরণের বদলে id, status, tracking |
| **আলাদা রাখো** (isolate) | ভিন্ন কাজ ভিন্ন context এ | Sales agent আর Delivery agent এর আলাদা context, একজনের ভিড় আরেকজনের ঘাড়ে না |

## Context খারাপ হলে যা হয়

| সমস্যা | কী ঘটে | উদাহরণ |
|---|---|---|
| **ভুল তথ্য রয়ে যাওয়া** | একবার ভুল কিছু context এ ঢুকলে model বারবার সেটার উপর ভর করে | কাস্টমার ঠিকানা বদলেছে, কিন্তু পুরনো ঠিকানাও history তে আছে, model পুরনোটা নেয় |
| **মনোযোগ হারানো** | অদরকারি জিনিসের ভিড়ে আসল কাজ মিস | পুরো catalog দেওয়ায় কাস্টমারের চাওয়া product এর দাম ভুল পড়ে |
| **বিভ্রান্তি** | অনেক বেশি tool, model ভুল tool বাছে | ৩০টা tool দেওয়া, যেখানে এই কাজে ৩টা লাগে |
| **পরস্পরবিরোধী তথ্য** | দুই জায়গায় দুই রকম কথা | নীতিতে ডেলিভারি চার্জ ৬০, পুরনো মেসেজে ৫০ |

এগুলোর বেশিরভাগই model এর দোষ না, context এর দোষ। তাই agent ভুল করলে প্রথম প্রশ্ন: **"model এর সামনে আসলে কী ছিল?"** LangSmith এর মতো tracing tool ঠিক এটাই দেখায়।

## আমাদের নিয়ম

1. **অবস্থা আলাদা রাখো:** কথোপকথন থেকে বের করা তথ্য (`OrderForm`) আলাদা জমা রাখো, প্রতিবার history থেকে নতুন করে বের করিও না।
2. **সর্বশেষ তথ্যই সত্য:** কাস্টমার কিছু বদলালে অবস্থা আপডেট করো, পুরনোটা context থেকে সরাও।
3. **Tool ফলাফল ছোট:** tool যেন শুধু দরকারি ঘর ফেরত দেয়।
4. **যে কাজ, সেই tool:** প্রতিটা ধাপে শুধু দরকারি tool দাও।
5. **স্থির অংশ শুরুতে:** নিয়ম আর উদাহরণ সবার আগে, বদলানো অংশ পরে। এতে prompt caching ও কাজ করে ([Inference Engineering](/ai-engineer/inference-engineering))।

## যা নিয়ে গোলমাল হয়

- **Context engineering নতুন কোনো প্রযুক্তি না।** এটা একটা দৃষ্টিভঙ্গি: prompt লেখা থেকে সরে, পুরো context এর নকশাকে আসল কাজ ধরা।
- **বড় context window থাকলেও এটা লাগে।** জায়গা বেশি মানে সব ঢুকিয়ে দেওয়া না। [Context Window](/ai-engineer/context-window) নোটের "বড় context মানেই ভালো না" দেখো।
- **Memory আর context এক না।** Memory হলো যা জমা আছে, context হলো এই call এ তার থেকে যা বেছে দেওয়া হলো।

এখান থেকে পরের অংশ: [Structured Output](/ai-engineer/structured-output) আর [LangChain এর মূল অংশ](/ai-engineer/langchain-basics), যেগুলো দিয়ে আমাদের agent বানানো শুরু হবে।
