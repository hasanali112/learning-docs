একটা request এর পুরো যাত্রা

Rust backend থেকে request আসে, Linux kernel পার হয়ে Python process এ ঢোকে। CPython VM তোমার কোডের bytecode চালায়, memory আসে kernel থেকে, আর শেষে সব কাজ করে RAM আর CPU। প্রথমে দেখো server চালুর সময় একবার কী হয়, তারপর প্রতিটা request এ কী হয়।

memory leak: কেন হয়, কীভাবে এড়াবে

    

      

        
১. request শেষেও কিছু ধরে রাখা


ALL_ORDERS = []
def create_order(order):
    ALL_ORDERS.append(order)  # কখনো মোছে না

        
global list বা dict এ প্রতিটা request এর জিনিস জমালে refcount কখনো ০ হয় না, pymalloc এর block ফুরায়, বারবার mmap হয়, RAM ভরে যায়। শেষে Linux এর OOM killer process বন্ধ করে দেয়। database এ রাখো, বা deque(maxlen=1000) এর মতো সীমা দাও। @functools.cache বা lru_cache(maxsize=None) সীমাহীন, তাই maxsize দাও।

      

      

        
২. বড় data একবারে memory তে আনা

        
পুরো file বা database এর হাজার হাজার row একসাথে পড়লে একটা request এই অনেক memory নেয়, আর বড় অংশ সরাসরি kernel এর mmap এ যায়। অল্প অল্প করে পড়ো: generator, pagination, streaming response। একসাথে অনেক request এলে এই পার্থক্য বিশাল হয়ে যায়।

      

      

        
৩. memory না কমা মানেই leak না

        
pymalloc kernel থেকে ১ MB এর খণ্ডে (arena) memory নেয়, পুরো খণ্ড খালি হলে তবেই ফেরত দেয়। তাই object মুছলেও htop এ সংখ্যা প্রায়ই কমে না। leak মানে request এর পর request memory বাড়তেই থাকা। একে অপরকে ধরে রাখা object (চক্র) মোছে garbage collector (gc)।

      

      

        
৪. leak খুঁজবে কীভাবে


import tracemalloc
tracemalloc.start()
snap1 = tracemalloc.take_snapshot()
# ... অনেকগুলো request পাঠাও ...
snap2 = tracemalloc.take_snapshot()
for s in snap2.compare_to(snap1, "lineno")[:5]:
    print(s)  # কোন লাইন সবচেয়ে বেশি বাড়াল

        
দুই সময়ের ছবি তুলে তুলনা করলে বোঝা যায় কোন লাইন memory জমাচ্ছে।
